# 审计 pool 清零时，用预填 NaN 区分有效输出与未写行

2026-09-10，一次 vLLM Ascend 持久输出 buffer 审计讨论能否删除 `out.zero_()`。所查 pool 只在压缩窗口完成时写对应输出行；未完成行和 padding 行会保留 `torch.empty` 或上轮执行留下的内容。整块 tensor 不一致不能直接证明有害，单看有效行一致也不足以宣布清零可删，必须继续检查后续读取和 cache 写入。

调查采用两种预填值：NaN 用于暴露未写内容参与计算，常数 17 用于确认无效行确实保留旧值。每个用例同时维护有效行集合，分别核对状态更新、有效输出和无效输出，而不是把全零输出作为参考的隐含前提。起始位置与请求长度一起变化，以覆盖窗口刚完成、仍有残留以及尾部 padding 等情况。

18 组真实 NPU 记录显示，状态与有效输出完全一致，后续实际执行的 norm、投影和量化在有效行上也一致；无效行则明确记录仍保留预填内容。图回放又改变输入及有效行集合，排除了固定 mask、固定数据恰好通过的情况。这组结果只说明已执行的局部消费者没有让无效行污染有效行，不能据此推断所有消费者都不读无效行。

该次审计中的生产代码仍保留 `out.zero_()`。RoPE 与最终 scatter 仅做了源码检查，完整消费者链的设备验证没有完成；因此这次产出是限定范围的审计结果，并未实施免清零优化。后续若删除清零，应继续沿“输出行—消费者—目标 cache 地址”证明无效行不会被发布，并把未写行的未定义语义写入测试。发现无效行 NaN 时，也应先检查它是否被消费，不能直接据此归因整网异常。
