# 将 K3 功能 CI 缩到四卡时，保留了哪些真正执行的路径

2026 年 8 月 31 日，Kimi K3 的功能回归从较大拓扑缩减到单节点 A3 四张逻辑 NPU。目标是尽快发现模型接线、算子和服务接口的错误。它使用本地生成的配置、tokenizer 和 dummy 权重，因此没有把完整 checkpoint、下载耗时或精度评估放进这个门禁。

缩减的是层数、专家总数和运行拓扑，保留了会影响算子与模型分支的宽度及混合结构：target 为六层、16 个 routed experts，保留 KDA、MLA 和结尾连续 MLA 层；Attention Residual block size 取 4，仍跨越残差块边界。hidden width 保留 7168，词表 163840。draft 的辅助层索引重新映射到缩减后的 target，避免沿用完整模型层号，导致测试虽小却根本走不到辅助特征路径。

输入直接构造 token IDs，历史实现为 `10 + (i + salt) % 1000`，salt 用于区分请求。离线生成设置 temperature 为 0、固定输出 2 tokens、忽略 EOS、不 detokenize，断言完成状态、输出长度及 token ID 范围。随机权重下有意义的是这些结构断言，不是输出文字是否自然。

四项实际执行的用例分别保留了以下观察点：

| 用例 | 四卡拓扑及具体触发 | 不能省略的断言 |
| --- | --- | --- |
| MLA draft | TP4；长度 1、127、128、129、769 等请求 | 输出长度／范围；draft counter 增长；缓存 reset 后冷请求确实创建缓存 |
| GQA W4A8 draft | DP2×TP2；四个并发请求，包括接近 max length 的输入 | 两个 engine 各自的 draft counter 都增长，不能只聚合成一个总数 |
| MTP 多模态 | TP4、eager；文本请求与一张程序生成的 56×56 RGB 图片 | 实际图片占位符及图像输入进入模型，MTP counter 增长 |
| MLA P/D | P 为 TP2、D 为 TP2，Mooncake connector | P 返回可用 `remote_block_ids`；D 接收原 transfer 参数；长于 1 token 的请求返回正的 cached tokens |

P/D 用例保持 producer／consumer 的 target 与 draft 布局一致，因为 producer 同样需要建立 draft KV。除长度 1、129、769 的传输请求外，还向 D 单独发送 513-token 请求，不附带 remote KV，覆盖 D 的本地 prefill fallback；否则只测 KV 传输可能掩盖 D 缺少该路径权重或初始化的问题。

这次四卡运行的 pytest 原始结果是 `4 passed`，约 332 秒；日志可见 world size 4、两组 DP engine、prefix reset 和 KV transfer。输出中仍有结束阶段告警，因此以 pytest 退出状态和请求断言判断功能结果，而非要求日志完全无 warning。

该批 prefix 部分只验证冷请求创建缓存，没有形成同一 prompt 的 warm 命中闭环；P/D 的 remote cached tokens 也不能替代本地 prefix cache 命中证据。dummy 权重不验证真实权重键、QuaRot、采信率、语义质量或吞吐。保留这些界限，四卡门禁才可以用于快速发现功能回归，而不会被误当作完整模型验收。
