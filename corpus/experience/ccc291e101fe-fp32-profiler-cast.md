# 两路投影共享 FP32 输入后，用真实 profiler 事件确认少了一次 cast

2026-09-09 至 09-10，检查 vLLM Ascend 一条双投影路径时，发现两个线性层各自调用同一输入的 `.float()`。修改先生成一个 FP32 tensor，再按原顺序交给两路投影，保持权重、投影顺序和输出不变。测试同时检查 FP32 输入本来就无需转换，避免把所有 dtype 都算成省一次 cast。

第一次 NPU probe 反而失败：脚本认定应出现两个 `aten::mm`，实际这条调用链报告的是 `aten::linear`、`aten::matmul` 和 `aclnnMatmul`。因此先修正观测指标，再核对计算是否真的保留。后续 18 组用例覆盖 BF16、FP16、FP32，三种 token 数及连续/非连续输入，eager 与改变输入后的图回放输出完全一致。低精度输入的转换计数从两次降到一次，两次投影仍在；FP32 的转换仍为零。

BF16、16 token 的局部图计时约为 26.98→24.73 微秒，128 token 也有小幅下降。它只证明这段双投影节省了重复转换，不能外推整网吞吐，也不说明其他投影可以共用输入。这个案例同时留下了观测工具的教训：事件名称假设失败时，先核实实际调用链，不能将计数断言失败直接解释为算子没有执行。
