# 合并重复 metadata 构建时，把物理地址留在缓存组内

2026-09-10，优化 vLLM Ascend 衍生模型的 metadata 热路径时，KV-group 循环反复计算同批请求的计数、长度与位置变换。直接将整个 metadata 对象移到循环外并不安全：不同组可能有相同逻辑长度，却使用不同物理 block，环形状态也由各组独立推进。

修改将缓存分成两个作用域，两个缓存都在每次 build 开始时重置：

| 作用域 | 当时复用的内容 | 保留的约束 |
| --- | --- | --- |
| 本次 batch 构建 | 请求统计、公共长度、位置与 RoPE，以及条件相同的算子 metadata | 按压缩条件等语义参数区分，不能跨新的输入批次复用 |
| 当前 KV 组 | slot mapping、组内环形状态、依赖 block table 的坐标 | 使用该组地址；缓存键还区分压缩条件与物理 storage block size |

共享的 batch 字典没有直接交给各组继续修改；每组先建立浅拷贝，再加入本组的坐标。这样既复用公共 tensor，又避免后处理把某组字段写回共享字典。依赖组地址的计算留在组缓存未命中分支，并删除了没有消费者的坐标计算。这个拆分比“shape 相同就复用”严格：逻辑请求序列相同，不能推出物理地址相同。

验证以独立构建为参考，使用不同 block ID 检查组间隔离，再在图回放中改变长度、物理块和 idle 输入。四项真实 NPU 用例通过，覆盖同步构建和 metadata stream；比较算子定义的有效 payload，而不是把保留区未定义内容也要求逐字一致。由此排除了只因测试恰好用了相同地址而出现的假正确。

原始 16 请求局部对照中，构建加设备同步约从 19.118 ms 降到 4.382 ms；单请求下改善较小。计时包含主机提交和同步，不证明异步重叠、整网服务或 TPOT 收益。另有三项回归失败在未修改基线上复现，不能称全仓通过。复用这次方法时，先按计算依赖拆分 batch 语义和组物理地址，再用会改变这些依赖的输入验证生命周期。
