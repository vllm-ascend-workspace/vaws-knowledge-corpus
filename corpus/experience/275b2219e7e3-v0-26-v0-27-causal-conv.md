# v0.26→v0.27 图回归调查中收窄 causal-conv 修改范围

2026-08-18 至 08-19，Kimi K3 从旧版本迁移到 v0.27 FULL 图后出现异常。初期同时修改了 recurrent KDA 的别名、causal-conv schema、padding 和 norm 等可疑契约；causal-conv 的四项 NPU 用例通过，却没有证明每一项都是整网回归的原因。

复查两个版本的图边界时，调查收窄到 `_run_causal_conv1d`。旧版本外层 `kda_attention` 隔离内部调用，新版本内部 causal-conv 会进入 functionalization。原调用分配 `output`，调用 `npu_causal_conv1d_custom`，却忽略算子返回值并返回原分配。eager 下原地写入可掩盖这件事；图变换若按声明的返回值追踪数据流，就不能依赖一个未在图中消费的副作用结果。

提炼后的调用差异如下，省略的是原调用保持不变的卷积状态、权重及 metadata 参数：

```python
# 原路径
output = torch.empty_like(mixed_qkv)
npu_causal_conv1d_custom(output, mixed_qkv, ...)
return output

# 收窄后的候选
output = torch.empty_like(mixed_qkv)
return npu_causal_conv1d_custom(output, mixed_qkv, ...)
```

单元对照的要点是让测试替身返回一个不同于传入 allocation 的 tensor，确认 wrapper 真正返回算子的返回值；若替身始终原地写同一对象，就测不到这个错误。下一步设备实验也被收窄为仅消费返回值，保留旧 kernel、binding 和 schema，避免再把多个修改绑在一起。

这一步最小 A/B 当时没有完成设备执行。前述四项 NPU 通过属于更宽的早期补丁，后来的 P/D 成功也不是“只改返回值”的独立因果实验。因此本篇记录的是有源码与调用测试支撑的契约差异，以及撤回过强根因判断的过程；不将候选写成已证明的服务根治。[迁移工作的历史上下文](https://github.com/vllm-project/vllm-ascend/pull/14454)。
