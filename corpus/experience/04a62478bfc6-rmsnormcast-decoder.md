# 融合 RMSNormCast 后，补上真实 decoder 的双输出接线

2026-09-09 至 09-10，一次 vLLM Ascend 归一化优化最初范围较宽。沿真实调用链复查后，部分 helper 只用于参考测试，另一些生产路径已经融合或回退，继续按函数名批量改造会改到无效入口。工作最终收窄到 decoder 中实际使用的归一化和路由消费者，接入同时返回低精度激活与 FP32 路由输入的 RMSNormCast。

双输出的契约是本次接入的关键。下面是从当时测试提炼的等价关系，不是另一个执行脚本：

```python
y_low, y_fp32 = rms_norm_cast(x, weight, eps)
# y_low 与原低精度 RMSNorm 输出按约定容差比较
# y_fp32 必须精确等于 y_low.float()
experts_input = y_low
router_input = y_fp32
```

FP32 输出不是归一化中间值保留更多精度的版本；必须保留低精度结果已经发生的舍入，否则融合会悄悄改变路由输入。测试因此拆成两类断言：低精度输出对原算子的数值比较，以及两输出之间的精确关系。仅断言 shape/dtype 正确不足以约束这件事。

调用链回归继续检查 decoder 把两个 tensor 传给同一次 MLP。MoE 测试组合了内部/外部 router、是否开启 token 分片、是否传入 FP32 旁路；分片时，专家输入与路由输入必须取对应的 token 区间，不能一份被切片、一份仍是完整 batch。缺少 FP32 旁路时仍验证旧转换路径，从而确认优化没有只修好算子单测、却让生产路径再次 `.float()` 或使用错误输入。

A3、CANN 9.1 的原始记录有 19 项 NPU 用例及两项 meta 检查通过，覆盖 FP16/BF16、两种维度和改变输入后的图回放；后续相关回归为 96 passed。某个 BF16、16 token 构造用例约从 7.90 降至 4.94 微秒。这证明了当时双输出实现与接线的局部效果，整模精度、吞吐和其他架构仍未验证，全仓格式检查也仍有失败。
