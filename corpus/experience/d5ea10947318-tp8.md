# 同机双 TP8 对照定位预分配残差切片的寻址回归

2026-08-21，Kimi K3 的 v0.26 与 v0.27 在相同缩减专家 QuaRot 权重、相同参数及 block size 768 下表现不同。为缩小变量，两套 TP8 服务放在同一台 A3 的不同卡组，固定输入后追踪首次分叉。

差别来自 Attention Residual 的输入布局。v0.26 动态拼接残差，v0.27 先分配容量更大的 buffer，再取前 B 个有效块。设容量为 C、hidden size 为 H，`storage[:, :B, :]` 的逻辑 shape 是 `[N,B,H]`，但 token stride 仍为 `C*H`。旧 Triton kernel 按 `B*H` 计算下一 token 起点，B<C 时就会读到其他容量位置或旧数据。

以下是原修改提炼出的地址关系，stride 单位是元素：

```text
旧：base + token*(B*H) + block*H + column
新：base + token*stride(0) + block*stride(1) + column*stride(2)
```

改动同时覆盖算 scores 和加权求和两次读取，以及 prefix-sum 的真实 stride；只修一处会留下另一条错误读路径。测试也不再只构造紧密输入：使用 7 token、hidden size 7168，先分配 `[N,B+extra_capacity,H]`，再取前 B 块，`extra_capacity` 分别为 0 和 3，与实际预分配切片同构。

修后保存了 16、17、18、31、32、127、128、129 等请求边界的两轮结果，输出与 logprob 对齐，汇总为 `stable=True`、`ALL_OK=True`。这不自动给出单项修改的吞吐收益，后续并发或 P/D 通过也不能重复计作同一个单变量实验。

后来的接口改为传完整容量 buffer 加有效块数；本文不要求新接口恢复任意 stride 方案。可复用的定位点是：shape 中的有效数量与底层 allocation 容量改变时，用同构 slice 测试实际寻址。[当时的模型集成 PR](https://github.com/vllm-project/vllm-ascend/pull/14600)。
